# 架构

## 依赖方向

```text
main.rs → lib.rs → app.rs
                    ├── icon.rs
                    ├── i18n.rs
                    ├── platform.rs → plugin/launcher/search.rs
                    ├── plugin/mod.rs
                    ├── plugin/api.rs
                    ├── plugin/host_view.rs
                    ├── plugin/protocol.rs
                    ├── plugin/launcher/
                    │   ├── search.rs
                    │   └── view.rs
                    ├── plugin/clipboard/
                    │   ├── mod.rs
                    │   └── view.rs
                    ├── plugin/json/
                    │   ├── mod.rs
                    │   └── view.rs
                    ├── plugin/yaml/
                    │   ├── mod.rs
                    │   └── view.rs
                    ├── plugin/translate/
                    │   ├── mod.rs
                    │   └── view.rs
                    ├── plugin/settings/
                    │   ├── mod.rs
                    │   └── view.rs
                    ├── plugin/shortcuts/
                    │   └── mod.rs
                    ├── plugin/system/
                    │   └── mod.rs
                    ├── state.rs
                    ├── theme.rs
                    ├── update.rs
                    └── network.rs
```

- `main.rs`：二进制入口
- `lib.rs`：GPUI 初始化和窗口创建
- `app.rs`：窗口、输入、系统事件和宿主能力适配
- `plugin/launcher/`：主页插件，包含搜索模型、匹配排序和主页视图
- `plugin/clipboard/`：剪切板插件，包含富内容历史、类型识别、排序、搜索、持久化和插件视图
- `plugin/json/`：JSON 编辑器插件，包含编辑器状态、校验、转换和草稿存储
- `plugin/yaml/`：YAML 编辑器插件，包含编辑器状态、校验、转换和草稿存储
- `plugin/translate/`：大模型翻译页面、自动方向识别、服务商配置和本地 API Key 存储
- `plugin/settings/`：设置宿主，负责分组展示插件贡献的设置项
- `plugin/system/`：系统级插件，提供主题、语言和面板尺寸偏好
- `plugin/shortcuts/`：全局快捷键与目标文本绑定及独立持久化
- `plugin/protocol.rs`：插件与宿主共享的结果、动作和应用条目协议
- `plugin/compare.rs`：JSON/YAML 双栏比较共用的状态、逐行差异范围和滚动同步逻辑
- `plugin/api.rs`：插件 trait、manifest、版本和权限声明
- `plugin/host_view.rs`：活动插件视图渲染与统一 `PluginEvent` 转发
- `state.rs`：跨插件的应用级偏好持久化
- `plugin/storage.rs`：按插件隔离的目录、原子写入和基础读写能力
- `icon.rs`：项目自绘 SVG 图标目录与渲染入口
- `i18n.rs`：语言选择与全部产品文案
- `platform.rs`：系统发现、打开操作、输入模拟和登录项管理
- `plugin/`：插件身份、状态、持久化和各自视图
- `theme.rs`：语义设计令牌与应用级尺寸
- `update.rs`：Apple Silicon macOS 的最新 GitHub Release 查询与更新判断
- `network.rs`：共享的 HTTPS Chat Completions 客户端，禁用重定向并解析兼容响应

`plugin/launcher/search.rs` 不依赖 GPUI，也不执行系统命令。平台差异限制在
`platform.rs`。

全局偏好使用版本化的键值配置保存到平台配置目录。插件状态仍由插件自己保存，只有
真正跨插件的应用偏好才进入 `state.rs`，避免把业务数据集中到宿主。

设置页使用 `SettingDefinition` 和 `SettingsChange` 协议。侧栏分为系统设置和插件设置；
插件入口从实际贡献的设置项生成，每个插件单独展示其选项。设置宿主只负责分组展示和
派发变更，不需要为每个插件增加专用页面分支。

普通插件通过 `PluginStorage::for_plugin` 获取自己的存储上下文，只能读写自己的目录。
插件负责数据格式、版本和迁移，存储层负责目录创建与原子替换写入。

## 界面基础

- 主题默认跟随系统明暗模式，并监听运行时变化。
- 页面从 GPUI Kit 读取语义颜色、间距、圆角和排版令牌。
- 窗口与图标等应用级尺寸集中在 `theme.rs`。
- 主面板可拖动边缘和四角调整尺寸，最小为 700×440；页面内容随窗口伸缩。
- 通用设置可将初始面板尺寸设为小（700×440）、中（760×560）、大（1000×760）或自定义；
  自定义宽为 700–2400、高为 440–1600，变更立即调整窗口并持久化。
- macOS 使用 AppKit 原生窗口调整尺寸，系统窗口按钮保持隐藏；其他平台使用 GPUI 客户端边框。
- 产品文案由 `i18n.rs` 按系统语言生成，当前支持简体中文和英文。
- 业务数据使用 `ResultKind`、`ResultTitle` 等语义类型，不保存翻译后的文本。
- Apple Silicon macOS 的通用设置从 GitHub Releases 查询最新版本并展示本地语言的更新说明；
  更新器在应用内下载对应 ARM64 DMG，用户确认“安装并重启”后由独立 helper 校验并替换当前 `.app`，再重新打开应用；
  当前安装目录不可写或安装失败时保留 GitHub Releases 手动更新入口。
- Release 由 `vMAJOR.MINOR.PATCH` 标签触发；工作流验证 `Cargo.toml` 版本和
  `CHANGELOG.md` 条目后，仅构建并发布 Apple Silicon macOS DMG。

新增页面不得写死颜色和产品文案。只有无法由语义比例表达的组件尺寸可以加入
`theme.rs`，且应按用途命名。

## 图标

- 内置操作图标保存在 `assets/icons`，统一使用 24×24 画布和主题语义色。
- 应用结果优先显示系统应用图标，加载中或解码失败时显示自绘 SVG。
- macOS 从应用包读取 ICNS，转换为 64px PNG 后缓存在
  `~/Library/Caches/io.github.jclee777.jump1/icons`，索引结果只保存文件路径。
- Linux 读取 `.desktop` 的 `Icon=`，解析常见图标主题中的 PNG、SVG 或 ICO。
- 扩展结果后续复用 `icon_path`，接受 SVG 或常见位图格式，并使用同一回退逻辑。

Windows 当前保留自绘回退图标；原生可执行文件图标提取放在 Windows 平台实现中，
不进入命令匹配层。

## 内置插件

`PluginId` 是当前应用内部的路由身份，不是对外插件 API。`PluginRegistry` 负责插件注册，
`PluginManager` 负责当前插件、查询分发和选中项激活，并在主页结果中组合各插件声明的
入口；应用壳只处理窗口、输入、系统事件以及打开应用、路径、网址等宿主能力。每个插件
自己拥有状态、搜索、持久化和视图。主页也是一个插件，默认路由为 `LauncherPlugin`。

`app.rs` 不导入具体插件视图，也不按插件类型渲染。插件层把点击、返回、复制和设置变更
转换为统一 `PluginEvent`，宿主只执行窗口、剪切板、主题和系统打开等能力。
编辑型页面可以声明自己的焦点目标；宿主切换页面或重新唤起窗口时优先恢复活动插件的
编辑器焦点，没有页面焦点的插件继续使用宿主搜索输入框。
设置变更由管理器应用并持久化，随后只返回 `HostEffect`；宿主不知道设置来源，也不处理
插件配置结构，只负责调用 GPUI 主题切换、更新当前语言服务和调整面板尺寸。macOS 登录启动使用系统
`SMAppService.mainApp` 注册，开关状态直接读取系统登录项，不在应用偏好中重复保存。

macOS 安装包在 `Info.plist` 中设置 `LSUIElement`，应用作为后台工具运行且不占用 Dock。
主窗口首次创建时显示，失去焦点后隐藏并保持后台服务，全局快捷键负责再次激活面板。DMG 打包入口为
`scripts/package-macos.sh`。本地临时签名显式使用基于 bundle ID 的稳定 designated
requirement，避免每次构建因默认 `cdhash` 要求变化而使辅助功能授权失效。

快捷方式保存“全局组合键 + 目标文本”，由设置页负责录制和编辑。触发后宿主把目标文本
交给主页搜索并执行第一项结果，因此应用中文名、拼音、插件关键词和后续扩展能力共用
同一套匹配与排序。全局事件只携带绑定 ID，执行时再从插件读取最新文本，编辑目标文本
不需要反复注销快捷键。每条绑定可以选择先向前台应用发送系统复制组合键，等待剪切板
刷新后再执行目标。绑定数据归快捷方式插件所有。

每个内置插件实现 `Plugin` trait，并通过 `PluginManifest` 声明 ID、版本和权限。插件
切换时由管理器调用启用和停用生命周期钩子。对外插件协议尚未确定，当前只注册内置插件。

生命周期由注册表记录：

```text
Registered → Loaded → Active ⇄ Suspended → Stopped
                         └──→ Failed
```

`page` 插件随页面切换激活和挂起，`service` 插件在应用期间持续运行，`hybrid` 插件同时
提供后台能力和页面。剪切板为 `hybrid`，系统插件为 `service`，因此关闭页面不会停止采集
或主题、语言服务。应用关闭时管理器统一调用 `on_shutdown`。

首个插件为剪切板历史：

- 启动后每 700ms 读取一次系统剪切板，记录文本、图片和文件路径。
- 文本和文件按内容识别 JSON、HTTP、Bash、PDF、Word、音频等常见格式。
- 页面可按复制时间或复制/粘贴次数排序，Tab 键保持并切换当前排序。
- 回车或点击会把历史内容写回系统剪切板，隐藏面板，再向原前台应用发送粘贴组合键。
  macOS 记录剪切板条目的原始数据类型并按类型写回，文件 URL 保持独立条目；使用系统会话事件发送 ⌘V。
- macOS 唤起面板前会记录原前台应用；粘贴时明确恢复该应用并确认焦点切换后再发送按键，
  避免 `LSUIElement` 后台应用隐藏时丢失粘贴目标。
- 历史数量支持 50、100、200 和无限；清空操作只清理插件历史，并忽略系统剪切板中
  尚未变化的当前内容，避免轮询立即把它重新收录。
- 开发期历史文件沿用 `HDCB2` 标记，当前结构包含 macOS 原始剪切板类型；不提供旧结构迁移。
- 相同内容去重并移动到最前，单条内容限制为 32 MiB。
- 历史使用带版本头的长度前缀二进制格式，损坏记录不会进入界面。
- 数据由插件存储边界写入各平台应用数据目录。
- 插件页面支持过滤、方向键选择、回车粘贴和 Tab 切换排序。右方向键展开选中项预览，
  左方向键或 Esc 关闭；文本显示正文，图片显示图像，文件显示路径信息。

JSON 编辑器是首个拥有独立代码编辑状态的页面插件：

- 使用 GPUI Kit `EditorState` 和 JSON Tree-sitter 高亮。
- 支持实时语法校验、格式化、压缩、递归键排序、复制和剪切板导入。
- 可切换左右对比；两侧独立编辑，对有效 JSON 按解析后的结构比较，忽略排版差异。
- 对比时两侧纵向滚动同步，并逐行标记文本差异；结构相同但排版不同会单独提示。
- 右侧对比草稿由 JSON 插件单独保存。
- 每次进入页面都会读取剪切板；内容是有效 JSON 时格式化后载入，无效内容保留原草稿。
- 草稿限制为 2 MiB，使用插件隔离存储延迟写入，只保留最后一份内容。
- 缩进宽度属于插件设置，可选择 2 或 4 个空格。
- 页面直接获得编辑器焦点，Esc 通过统一插件事件返回主页。

YAML 编辑器沿用相同的页面插件边界，并使用独立状态：

- 使用 YAML Tree-sitter 高亮和 `serde_yaml_ng` 进行实时解析校验。
- 支持格式化、递归键排序、复制、清空和剪切板导入。
- 可切换左右对比；两侧独立编辑，对有效 YAML 按解析后的结构比较，忽略排版差异。
- 对比时两侧纵向滚动同步，并逐行标记文本差异；结构相同但排版不同会单独提示。
- 右侧对比草稿由 YAML 插件单独保存。
- 每次进入页面时只自动载入映射、序列或带标签的结构化 YAML，避免普通剪切板文本覆盖草稿。
- 草稿与 2/4 空格编辑缩进分别保存在 YAML 插件目录。

翻译插件使用共享 Chat Completions 客户端，支持 OpenAI、DeepSeek 和自定义兼容接口；根据原文中的汉字自动选择中文译英文或英文译简体中文。服务商、模型、接口地址和 API Key 保存在翻译插件目录的本地配置文件中，API Key 以明文存储。翻译页允许手动输入或读取剪切板文本，结果不持久化，可复制回剪切板。网络请求在后台执行，原文长度限制为 32 KB。

## 功能模型

功能包含 ID、名称、来源、输入类型、匹配规则和执行动作。匹配层合并并排序内置与扩展结果，执行层负责调用、取消和错误反馈。

`SearchResult` 和 `CommandAction` 目前属于主页插件内部模型，不是对外插件 API。
